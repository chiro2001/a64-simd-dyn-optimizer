# 常量重排方向（内部 DCT16/DCT32 参考线索，2026-08-13 用户输入）

## 用户输入

> 内部的 DCT16/DCT32 SVE256 算子通过完全且充分地对常量进行重排，
> 大幅度减少了重排相关指令，完成了性能提升 30%~60%。

这是此前一直缺失的"结构差距"线索：优化目标不在数据侧 peephole，而在
**把运行时的数据重排（rev/zip/trn/tbl）吸收进编译期的常量布局**。

## 已核实的数学事实（DCT8/DCT16 均为逐 lane 系数）

奇数输出是逐 lane 的点积：

```
res_k_pre[l] = Σ_j g_t[k][j] * O_l[j]      // 系数随 lane j 变化
```

因此 proto_b 的 4×4 转置**不是**可消除的开销：转置把"对 lane 的点积"
换成"对向量的 splat 乘 + mla 链"。曾尝试免转置形式
（`89·O0+75·O1+50·O2+18·O3`，系数当 splat）——它计算的是
`Σ_k c[k]·O_k[l]`，与正确语义不同，qemu 差分 20000/20000 失败，已删。

## 常量重排的正确作用点与权衡（量化）

能被常量重排消除的是 **stage-1 偶数路径的数据 permute**：

- DCT16 stage-1 每 2 行有 `rev16×2 + rev32×2 + zip1 + zip2 + rev64`，
  8 个行对 ≈ **56 条 permute/pass**（两 pass ≈112）；
- 这些 permute 把 raw E 变换成 EE/EO/EEE/EEO，再乘 t8_even 常量；
- 把变换展开成对 raw E 的**预置换 8 系数常量**的点积（例如 res4 对应
  `[83,36,36,83,83,36,36,83]·E`），运行时 permute 归零。

代价是乘加数：4 个偶数输出共享同一 E，稠密形式每个输出要 8 mul + 7 add
（每行 60 ops），而结构化形式每 2 行只有 ~14 ops 的 E-combine + 输出级
乘加。**在 NEON 128-bit 上稠密形式必然亏损**（静态估算 DCT16 偶数路径
稠密约 960 ops/pass vs 结构化约 132 ops/pass）。

推论：内部实现的 30~60% 来自 **SVE256 宽度**下该权衡反转——SVE 的
permute 是 tbl/splice（贵），且 DCT16/DCT32 的 E 行是 8/16 lane，正好
一条 SVE256 s32 向量，稠密点积（svmul + 归约）相对结构化 permute 链
明显占优；此外奇偶 8×8/16×16 常量矩阵可能存在对称性分解（Chen/Loeffler
类），进一步减乘。具体分解仍需内部反汇编校准。

## 后续实施路径（下一步）

1. DCT16 SVE256（固定 VL=256）先按"raw E + 预置换常量点积"实现偶数
   路径，qemu 上游位级一致（合同见 04-validation-benchmark.md V0.5；
   无上游对照时才用 C-exact）+ 静态指令数对比，验证常量重排方向在
   SVE 上的收益量级（不需要 N+2 即可拿到静态证据）；
2. 奇数路径的 8×8/16×16 常量矩阵对称分解；
3. 两机实机（NEON 版对照）确认方向后，DCT32 复用。
