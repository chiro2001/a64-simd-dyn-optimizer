# AGO：AArch64 SIMD Graph Optimizer（规划，2026-08-16，round-0023 修订）

## 1. 愿景

把工具从“布局搜索 + 专用发射器”升级为后端式自动图优化：

```text
kernel 语义/契约 ──► 自动建图（输入/输出/计算节点）
        ──► Pass 管线（逐个 pass 优化，固定点迭代）
        ──► 目标机代价指令选择（最小延迟×吞吐×寄存器压力）
        ──► 验证（20k + 生产逐调用差分 + canary）
        ──► 真机反馈（N1 PMU / 920B CNTVCT 回放）→ 代价表更新 → 重选
```

AGO 与现有布局搜索**并行**（`--backend ago` 接入 search_sve2_layouts），
不破坏已验证的注入/冻结链路；OpIR 的重写规则作为 AGO 早期 pass 集，
已有人工赢法（查表 PEXT、DFA 状态表、全展开、NEON 尾部语义）沉淀为
可组合 pass/模板。

## 1.5 round-0023 决策要点（采纳）

- **顺序**：先最小类型化语义/Pack/Machine IR 契约 → SA8D 8x8 垂直切片
  （手工/导入图 + 复现上游 NEON，经 cover/schedule/real allocation/
  final-object 校验）→ 受限自动前端 → 第二个数据流锚点 + 有界
  cover 搜索 + 留出集代价排序 → 显式 loop/FSM 模板 → 现有
  --backend ago 注入/冻结集成。
- **语义权威**：契约 + 规范 DSL/受限 C 自语义为权威；intrinsics/汇编/
  反汇编/trace 只是证据，不是语义权威。
- **Pass**：不用全局固定点；用 phase ordering + 可执行前置/后置检查 +
  确定性规范哈希 + 递减度量 + 循环检测 + 硬预算。
- **指令选择**：有界 region → layout → cover → schedule → allocation
  搜索；上游 MachineIR 基线必须始终可选中。
- **Lowering**：intrinsic/DSL 与直接汇编两条都保留；最终链接对象
  反汇编与 spill 作为门禁。
- **代价模型**：N1 与 920B 分开维护；whole-kernel residual 不得直接
  改写单指令延迟/吞吐；先审计测量工具再标定。
- **过渡**：按家族独立过渡，两个 release 满足干净重建/正确性/ISA/
  目标非劣后，才把旧发射器移出活动注册表（保留为回归 oracle）。

## 2. 架构模块

| 模块 | 职责 | 输入 → 输出 |
| --- | --- | --- |
| Frontend / GraphBuilder | 从 manifest 契约、C 参考、种子、反汇编自动构建类型化数据流图 | kernel+契约 → AGO IR（SSA DAG + 形状/步长/常量表） |
| AGO IR | 统一中间表示，跨 kernel（熵/像素/变换） | — |
| Pass 管线 | 规范化、数据流变换（查表化/DFA 化/全展开/融合/重排合并）；phase ordering + 可执行前后检查 + 递减度量 + 循环检测 + 预算（非全局固定点） | AGO IR → AGO IR |
| Instruction Selection / Tiling | 有界 region → layout → cover → schedule → allocation 搜索；**目标集 = neon（N1/920B）与 sve1.0（920B VL=256）**；候选（模板/sdot/mla/查表）；上游 MachineIR 基线可选中 | AGO IR → 目标指令序列 |
| Cost Model | N1 与 920B 分表；来源：LLVM N1 .td + GCC 模型 + N1 PMU 校准；920B 仅 CNTVCT 形状级回填；residual 不得改写单指令代价 | 目标机描述 → 代价表 |
| Verification | 复用 20k 差分 + 生产逐调用差分 + canary | 目标指令序列 → PASS/FAIL |
| Feedback Loop | 候选 → 真实分布回放/PMU → 代价表更新 → 重新选择 | 实测数据 → 代价表 delta |

## 3. 与现有工具的关系

- `search_sve2_layouts.py` 新增 `--backend ago`：与 `acle/asm/op/gen` 并列，
  走同一验证/代理/注入链；
- `optimizer/ir/*`（OpIR、rewrites、asm_ir、analysis）作为 AGO 的雏形：
  rewrites 升级为带不变量/收敛性的 pass；asm_ir 升级为 GraphBuilder 的反向输入；
- `build_preload_so.py` / `cloud-e2e-inject.sh` / `freeze-best6b.sh` 不变，
  AGO 产出按同一冻结流程发布。

## 4. 目标机利用

### 4.1 Neoverse-N1（129.146.162.16，CPU part 0xd0c）

- 有 PMU：`perf stat -e cycles,instructions,...` 可用；NEON 4x128 + dotprod，
  无 SVE——与 920B 的 NEON 同宽，可作 NEON 代价标定与工具水平验证台；
- LLVM 源码已有 `AArch64SchedNeoverseN1.td`（延迟/吞吐表可提取）；
- GCC 模型 `gcc/config/aarch64/aarch64-sched-neoverse-n1.cc`（GCC 14+）
  需单独获取（本地无 gcc 源码，可网络下载单文件或 apt source）；
- 计划：先提取 LLVM N1 表 → 用 N1 PMU 微基准校准 → 作为 AGO 默认 NEON
  代价表；920B 用 CNTVCT 批量微基准把 SVE 部分回填。

### 4.2 920B

- 无 PMU，继续用 CNTVCT + 真实分布回放；代价表只标定到 kernel/形状粒度，
  指令级代价以 N1 表 + LLVM 数据交叉。

### 4.3 SVE1.0 作为一等搜索目标（2026-08-16 用户拍板）

- 920B 是 SVE1.0 2x256 + NEON 4x128；上游 x265 仅有 NEON，SVE1 是
  内部手写算子 30%+ 优势的主战场；
- AGO cover/搜索/预测/验证全链路把 `sve1` 作为与 `neon` 并列的目标
  ISA（manifest.isa="sve1"、-march=armv8.2-a+sve、check_isa_level
  门禁、920B SVE 成本表排序 + 实机 paired 回填）；
- 现有 gen 后端 `--isa sve1` 的候选是搜索起点，AGO 排序器负责从中
  选出 920B 实测非劣/更快的实现；
- SVE1 宽度优势依赖连续多行/宽行访问（dct 行、interp 横向、packed
  sad/satd stride=16）；小 stride 非连续块按行处理时不强行扩宽。

## 6. 风险

- 自动建图对状态机类 kernel（c1c2/remain）建模成本高：M3 显式模板化，
  不要求自动发明；
- 920B 无 PMU：指令级代价只能靠 N1 + LLVM 表外推，需在验收中容忍偏差；
- 与现有工具并存会增加维护面：AGO 独立目录（`optimizer/ago/`），
  不侵入已验证链路。
