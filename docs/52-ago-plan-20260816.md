# AGO：AArch64 SIMD Graph Optimizer（规划，2026-08-16）

## 1. 愿景

把工具从“布局搜索 + 专用发射器”升级为后端式自动图优化：

```text
kernel 语义/契约 ──► 自动建图（输入/输出/计算节点）
        ──► Pass 管线（逐个 pass 优化，固定点迭代）
        ──► 目标机代价指令选择（最小延迟×吞吐×寄存器压力）
        ──► 验证（20k + 生产逐调用差分 + canary）
        ──► 真机反馈（N1 PMU / 920B CNTVCT 回放）→ 代价表更新 → 重选
```

AGO 与现有布局搜索**并行**（`--backend ago` 接入 search_sve2_layouts），
不破坏已验证的注入/冻结链路；OpIR 的重写规则作为 AGO 早期 pass 集，
已有人工赢法（查表 PEXT、DFA 状态表、全展开、NEON 尾部语义）沉淀为
可组合 pass/模板。

## 2. 架构模块

| 模块 | 职责 | 输入 → 输出 |
| --- | --- | --- |
| Frontend / GraphBuilder | 从 manifest 契约、C 参考、种子、反汇编自动构建类型化数据流图 | kernel+契约 → AGO IR（SSA DAG + 形状/步长/常量表） |
| AGO IR | 统一中间表示，跨 kernel（熵/像素/变换） | — |
| Pass 管线 | 规范化（常量折叠、形状归一）、数据流变换（查表化/DFA 化/全展开/融合/重排合并）、目标无关优化；每个 pass 声明前置/后置不变量与代价影响，固定点迭代 | AGO IR → AGO IR |
| Instruction Selection / Tiling | Op 节点 → 目标 ISA 指令子集覆盖，候选匹配（模板/sdot/mla/查表），代价最小化（延迟×吞吐×寄存器压力/spill） | AGO IR → 目标指令序列 |
| Cost Model | 指令延迟/吞吐/端口表；来源：LLVM `AArch64SchedNeoverseN1.td`、GCC aarch64 调度模型、N1 PMU 实测校准、920B CNTVCT 批量微基准回填 | 目标机描述 → 代价表 |
| Verification | 复用 20k 差分 + 生产逐调用差分 + canary | 目标指令序列 → PASS/FAIL |
| Feedback Loop | 候选 → 真实分布回放/PMU → 代价表更新 → 重新选择 | 实测数据 → 代价表 delta |

## 3. 与现有工具的关系

- `search_sve2_layouts.py` 新增 `--backend ago`：与 `acle/asm/op/gen` 并列，
  走同一验证/代理/注入链；
- `optimizer/ir/*`（OpIR、rewrites、asm_ir、analysis）作为 AGO 的雏形：
  rewrites 升级为带不变量/收敛性的 pass；asm_ir 升级为 GraphBuilder 的反向输入；
- `build_preload_so.py` / `cloud-e2e-inject.sh` / `freeze-best6b.sh` 不变，
  AGO 产出按同一冻结流程发布。

## 4. 目标机利用

### 4.1 Neoverse-N1（129.146.162.16，CPU part 0xd0c）

- 有 PMU：`perf stat -e cycles,instructions,...` 可用；NEON 4x128 + dotprod，
  无 SVE——与 920B 的 NEON 同宽，可作 NEON 代价标定与工具水平验证台；
- LLVM 源码已有 `AArch64SchedNeoverseN1.td`（延迟/吞吐表可提取）；
- GCC 模型 `gcc/config/aarch64/aarch64-sched-neoverse-n1.cc`（GCC 14+）
  需单独获取（本地无 gcc 源码，可网络下载单文件或 apt source）；
- 计划：先提取 LLVM N1 表 → 用 N1 PMU 微基准校准 → 作为 AGO 默认 NEON
  代价表；920B 用 CNTVCT 批量微基准把 SVE 部分回填。

### 4.2 920B

- 无 PMU，继续用 CNTVCT + 真实分布回放；代价表只标定到 kernel/形状粒度，
  指令级代价以 N1 表 + LLVM 数据交叉。

## 5. 里程碑与验收

| 里程碑 | 内容 | 验收 |
| --- | --- | --- |
| M0 | AGO IR + GraphBuilder（先接 scanPosLast 或 dct8 小 kernel）+ N1 PMU 代价表原型 | 能对 1 个 kernel 自动建图并输出可验证候选 |
| M1 | Pass 管线（规范化 + 2-3 个数据流 pass，固定点迭代）+ NEON 子集覆盖式指令选择 | 在 N1 上 PMU 实测候选优于上游 NEON 的 kernel 出现 |
| M2 | 920B CNTVCT 回放反馈闭环（代价表随真机更新） | 候选在 920B 真实分布回放 ≥1.15× |
| M3 | 扩展到熵族/像素族赢法沉淀的 pass/模板 | 已有 7 个赢法可在 AGO 框架内表达并复现 |
| M4 | 与注入/冻结流程整合 | best7 可由 AGO 流水线重建 |

## 6. 风险

- 自动建图对状态机类 kernel（c1c2/remain）建模成本高：先以“数据流为主、
  状态机为辅”的混合图，或把状态机 kernel 的赢法作为模板而非自动生成；
- 920B 无 PMU：指令级代价只能靠 N1 + LLVM 表外推，需在验收中容忍偏差；
- 与现有工具并存会增加维护面：AGO 独立目录（`optimizer/ago/`），
  不侵入已验证链路。
