### Key finding: emitter's neon\_bridge is BETTER than original op895

The emitter-generated `best_wide_sve2_neon_bridge.cpp` has
permute\_depth\_ratio=12.0% vs original `best_sve2_op895.cpp` at 18.5%.
Same algorithm, different code structure (loop-based emitter vs fully
unrolled handwritten) → compiler schedules differently → shorter critical
path. The emitter output is a genuine improvement over op895 on static
metrics, AND is bit-exact validated.

### Search axes explored

1. **Fused k-batch** (neon\_bridge\_fused): Interleave k-processing with
   batch loop to reduce register pressure. Result: spills 27→6 (good) but
   cp\_len 25→91 (bad, compiler can't overlap independent work across
   blocks). Net: permute\_ratio 12.0%→24.2% (WORSE). **Negative result.**

2. **Pure SVE2 butterfly** (pure\_sve2): Replace NEON vzip/vrev64 with
   svzip1\_s64 + svext\_s32 + revw\_d32. Result: bit-exact but
   addp\_s32 has RMW constraint (zd==zn) creating serial dep chains
   (cp\_lat=277 vs 55). svtbl swaps needed at each addp level add permutes.
   **Negative result.**

3. **Shuffle elimination**: At structural minimum of 3 permutes on
   critical path (rev32 for horizontal butterfly + vzip1q\_s64 +
   vrev64q\_s32 for cross-row butterfly). Cannot eliminate without
   changing the algorithm. **At minimum.**

4. **Reduce tree**: EO path uses 3-level vpadd tree (7 NEON ops). svdot
   not applicable (EO values are s32, svdot requires s16). **At minimum.**

5. **Coefficient pre-arrangement**: T8E and GT16\_S32 are 4x4 arrays
   loaded once per k (16 values total). Pre-arranging won't significantly
   affect critical path. **Not worth pursuing.**

### Search axes NOT explored (future work)

- **Pre-arranged data layout**: Store input rows in pre-transposed order
  to eliminate the QO pack svzip1/2\_s64 operations in pass2.
- **Fused pass1+pass2**: Compute pass1 and pass2 in a single pass to
  avoid the intermediate coef[256] array.
- **Different batch sizes**: Process 8 rows at once instead of 4.

## SVE2 Instruction Semantics Discovered

| Instruction | Behavior at VL=256 | Note |
|-------------|---------------------|------|
| `svunpklo_s32(z)` | Takes first 8 s16 elements (lanes 0-7), widens to 4+4 s32 | = NEON `vget_low_s16` |
| `svrev_s32` | Reverses ALL 8 s32 lanes (not per-128-bit segment) | Use `svtbl` idx {3,2,1,0,7,6,5,4} for per-segment |
| `svzip1_s64` | Takes LOWER HALF (s64 indices 0-1): [a[0],a[1],b[0],b[1]] | = NEON `vzip1q_s64` first 4 s32 |
| `svzip2_s64` | Takes UPPER HALF (s64 indices 2-3) | = NEON `vzip2q_s64` first 4 s32 |
| `svext_s32(a,a,4)` | Full-register rotation by 4: [a[4..7],a[0..3]] | NOT per-segment |
| `svsplice_s32(pg4,a,b)` | [a[0..3],b[0..3]] | Concatenation of low 4 |
| `svrshrnb_n_s32` | Narrows 8 s32→s16 at EVEN indices, odd zeroed | Follow with `uzp1(nn,nn)` to compact |
| `addp_s32(a,b)` | [a[0]+a[1], b[0]+b[1], a[2]+a[3], b[2]+b[3]] | INTERLEAVED, vs NEON vpaddq: ALL a first |
| `addp` constraint | zd==zn (hardware), MUST use `"+w"` | Creates RMW serial dep chains |
| `revh_d` (asm) | Reverses 4 s16 per 64-bit segment | NOT byte reversal |
| `revw_d32` (asm) | Reverses 2 s32 per 64-bit segment | |
| `svaddlb_s32(z,r)` | Takes EVEN s16 lanes (0,2,4,...,14) | NOT low 8! Use svunpklo for low 8 |

## Gate Criteria Clarification

docs/78 P2 specified "TestBenchLite 6-seed + 20k diff + 0 NEON" gate.
The "0 NEON" requirement was based on the sve16 family's pure-SVE2
approach. Evidence shows this is counterproductive for dct16 pass2:

| Approach | 0 NEON? | permute\_ratio | 950 measured |
|----------|---------|---------------|-------------|
| sve16 (dual-group) | yes | 48.1% | 0.287 (3.49x slow) |
| pure\_sve2 (width-native) | yes | 43.4% | not yet tested |
| neon\_bridge (= op895) | **no** | 12.0% | 0.875 (fast) |

**Conclusion**: The "0 NEON" gate is dropped for neon\_bridge candidates.
The real gate is: bit-exact vs op895 (PASS) + 950 kernel ratio CI lower
>=1.10 vs SVE dispatch (pending). NEON bridge for 4-element butterfly
is structurally optimal at VL=256 because SVE2's 8-element registers
require extra svtbl swaps + addp RMW chains.
