## 0.1 顶层约束更新（2026-08-14，用户拍板）

- **项目周期内无 960 实机**：MCA（NV2 代理 + 950 校准权重）与 QEMU
  是最终性能/正确性代理；SVE2p3-only 内核（interp8 path-B、interp4）
  只做内部优化与模型预估，不做实机验收；
- **达标内核仅保留项目内部**：不做 x265 上游 PR；注入补丁留在仓库
  （integrations/），950 实测达标为“工具优秀”标志；
- **两个主攻方向**：① MCA 标定校准（用 950 真机数据拟合指令类权重）；
  ② 全算子覆盖搜索——研究如何快速对 x265 全部 SIMD 算子完成
  覆盖搜索与优化（docs/37）。

## 1. P0：实机验收闭环（最高优先，主要依赖硬件/Agent）

1. **920B 补测**：
   - `dct8` 已测（samples=50，NEON 3 / cand 4 = 0.75，与 docs/31/云
     一致）；注意 920B 上 cand **慢** 而 950 上 **快 1.483**——
     SVE/NEON 管道平衡随硅片变化（docs/34 §2.3）；
   - `ipb16` 云/内网分歧（0.872 vs 0.667）：云主机重测（>60 对、固定核）。
2. **950 第二轮**：确认未覆盖项（interp4 不能原生；idct16/32 已有替换
   下界；可补跑 interp8 hpp path-A 8x8 原生 + dct16 的 sve2 替换）。
3. **960 实机验收**（最终裁决）：interp8 hpp path-B 三形状、interp4
   16/32、idct16 分歧。命令已就绪（docs/27/32 模式）。
4. **950 达标 4 kernel 注入**（sa8d16/ivpp16/ivpp32/dct8）：x265
   dispatch 接入 + TestBench 全量 + 收益聚合（需要用户决定是否走注入）。

## 2. P1：MCA 模型修正（950 真机校准驱动）

1. **NV2 代理系统性低估 SVE256**（950 实测：vpp/dct8“判慢实快”）：
   - 用 950 实机 paired 做指令类权重拟合（dot/permute/load/store/mla
     的 cycle 权重），产出 `kunpeng-950` 校准权重（optimizer/mca_targets.py）；
   - 或等 960 数据后直接标定 NP1 4×256 模型；
2. **920B 替换口径量化**：BtoS 替换的 dot 工作量因子（2×）做成模型参数，
   让“上界/下界”可计算，而不是定性；
3. 搜索排序：把校准权重纳入 consensus（如 MCA 与 vector-lb 的权重按
   950 相关性调整），950/960 实机仍是最终裁决。

## 3. P2：工具继续进化

1. **interp8 hpp path-B 的 960 轴**：当前 permute（tbl/uzp）是瓶颈；
   950 实机显示 path-B 不采用，但 960（4×256）可能反转。预留/新增轴：
   - 窗口构造（tbl vs splice/ext）、双行批处理、uzp 合并存储；
   - 把这些轴接到 interp8-16/32 manifest 上做搜索（960 数据回来后）。
2. **注入自动化**：把“候选→x265 dispatch patch→TestBench 全量→
   paired 验收”脚本化（现有 build-testbench-inject.sh 偏手动）。
3. **融合分析升级**：等 960 微架构融合表确认后，把 eligible 对从“记录”
   转为搜索排序信号（docs/09 约束解除条件）。
4. **直接 asm 后端实验**（用户早期方向，docs/28 已止损）：用 interp4/
   interp8 的小结构作为载体，评估“发射器直接出 asm”对工具链的简化
   收益；不做大改，先做可行性原型。
5. **结果回填常态化**：parse_quick_report + reports/ 目录规范；
   云/内网 920B 差异跟踪表。

## 4. P3：新算子族候选（按性价比排序）

1. **interp4 vpp（chroma 垂直 4-tap）**：滑动行管线（4 行驻留 + 每行
   1 次新行加载 + 4×MLA），预计与 luma vpp 同量级收益（950 已证 vpp
   方向 +12%/+13%）；SVE2 即可（mla 是 SVE1），950 原生可测。
2. **sad/satd 家族（pixel SAD 16x16/32x32）**：SVE256 宽度利用率高；
   SATD 已有 sa8d16 经验，SAD 更简单。
3. **sa8d 8x8 或 sa8d32**：8x8 小形状难有收益（950/920B 结论一致），
   sa8d32 若 x265 使用可评估。
4. **quant**：标量重、SIMD 收益不确定，放最后。
