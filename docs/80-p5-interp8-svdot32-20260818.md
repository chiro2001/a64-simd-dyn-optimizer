## Key insight

`svdot_s32(acc, a.b, b.b)` outputs 8 s32 per lane at VL=256, mapping 1:1
to 8 output pixels. This eliminates the `addp` pair-sum step that is the
RMW bottleneck of `svdot_s64` (which outputs 4 s64, requiring `addp_s32`
with `zd==zn` constraint to merge paired lanes into 8 pixels).

**DC offset trick**: subtract 128 from u8 to get s8, accumulate
f*(s-128) = sum f*s - 8192, re-add 8192 via acc init = `svdup_n_s32(8192)`.
Unlike sdoth's s16 accumulator (needs 4096+4096 split across paired
lanes), s32 fits the full 8192 in a single lane.

## How it works (8x8)

```
Per row (r=0..7):
  W = svld1_u8(row-3)            // 32-byte window: src[-3..28]
  W -= 128                        // u8 -> s8 (DC offset trick)
  X0 = svtbl_s8(W, IX0B_U0)      // gather tap 0-3 for 8 pixels
  X1 = svtbl_s8(W, IX1B_U0)      // gather tap 4-7 for 8 pixels
  t = svdot_s32(off8192, X0, c0) // 8 s32: pixel[p] += c[0..3]*s[p-3..p]
  t = svdot_s32(t, X1, c1)       // 8 s32: pixel[p] += c[4..7]*s[p+1..p+4]
  rr = svrshrnb_n_s32(t, 6)      // 8 s32 -> 8 s16 (round shift right)
  rz = svuzp1_s16(rr, rr)        // compact to low 8 s16
  u8 = vqmovun_s16(rz)           // NEON bridge: s16 -> u8 (saturating)
  vst1_u8(dst, u8)               // store 8 pixels
```

## Multi-unit window reuse (16x16/32x32)

- 32-byte window covers 3 consecutive 8-pixel units (offset 0/8/16)
- n_windows = (units + 2) // 3
- Window q loaded at `row + 24*q`
- Unit u uses window q=u//3, offset o=(u%3)*8
- Index vectors IX0B_Uu = IX0B_BASE + (u%3)*8
