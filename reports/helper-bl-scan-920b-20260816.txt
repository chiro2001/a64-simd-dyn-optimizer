# 920B libx265 NEON helper 外链扫描（2026-08-16）

方法：objdump -dC + nm 归属，统计 libx265.so.216 中所有对匿名命名空间
helper 的 `bl` 调用（GCC12 外链 static inline 的栈往返缺陷）。

## 结论

1. satd 家族外链（hadamard_4x4_quad、pixel_satd_8x16/16x8）已通过
   内联候选修复并注入（E2E -1.76%）；
2. **下一个同型机会：interp8 filter8_u8x16 外链**（vps 家族，真实
   热点，profile interp 合计 ~5%）。复制上游 filter 实现为全内联
   候选，预期 1.3x+，语义 bit-exact，零算法改动；
3. interp4 filter4_sp/ss 与 sa8d 32/64 形状次优先；
4. C 模板静态实例（satd_8x4/satd_4x4）调用点多但 perf 无热点，
   暂不处理。

## 更新 2（2026-08-16 psy-cost）

- psyCost_pp 内联候选（4 形状，calc_energy_8x8 + hadamard 全内联）
  20k 差分 0 失配；
- 920B paired：8x8 1.19x（274 vs 230 ticks）、16x16 0.99x、
  32x32 1.00x、64x64 0.99x——**calc_energy 外链只存在于 8x8 路径**
  （psyCost_pp_neon<1>），16/32/64 无外链无收益；
- 结论：psy-cost 注入价值低（8x8 收益边际且非热点），不纳入；
- 外链修复线收尾：satd 家族 ✓、interp8 vps ✓、interp8 hps ✗、
  psy-cost ✗（边际）；interp4 filter4 外链属低热点路径（不优先）。

## 更新 3（2026-08-16 SVE1 quant 可行性）

- 尝试为 quant（2.59% + signBitHiding 协同）设计 SVE1 候选：核心
  是 abs(coef)*quantCoeff 的 s16 x s32 -> s32 展宽乘；
- 结论：**不可行**——SVE1 无 SMULL/SMLAL（SVE2），且 SXTH/SXTW
  的 64-bit 段内采样语义（每段取前 2 个源元素）会打乱 16 个 s16
  到 s32 的索引，需要多次 permute 重组，指令数爆炸；
- quant/dct32/dct16 的算法级优化在 920B 上（SVE1 缺宽乘 + 上游
  NEON asm 已紧凑）证据上不可行；剩余路径为 950 SVE2 实测窗口。
