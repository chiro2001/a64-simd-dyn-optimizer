# motionEstimate 像素族真实调用计数（2026-08-15，round-0022 P1）

目的：在生成任何新候选之前，先测 sad/sad_x3/sad_x4/satd/pixelavg_pp/
sa8d 各形状在 30 帧 1080p 编码中的真实调用次数，计算可节省上限。

## 方法

`tools/trace_pixelcmp_calls.py` 生成计数包装器（atexit 打印），patch 进
生产 lib；码流保持 ee5db7 一致。槽位 id 见生成器注释。

## 调用计数（30 帧）

| 槽 | 形状 | 调用次数 |
| --- | --- | ---: |
| sad | 8x8 / 16x16 / 32x32 / 64x64 | 8,309,024 / 1,213,201 / 676,954 / 28,239 |
| sad_x3 | 8x8 / 16x16 / 32x32 / 64x64 | 2,738,909 / 387,215 / 199,704 / 7,676 |

（chroma satd 槽无计数：本配置下未被调用。）

## 结论（measure-before-generate）

1. **satd 8x8 是绝对大头（1652 万次）**，已由注入的 satd8 候选覆盖
   （+8%）；perf 中 satd8<8,8> 占 0.93%，折算 ~4.6 ticks/次。
2. sa8d 4x4+8x8（1140 万次）无可用候选：sa8d-8x8 旧实测 0.434
   （慢 2.3×，docs/48），16x16/32x32 已注入（~1.0）。
3. sad 8x8（831 万次）候选慢 1.8×（78 vs 43 ticks/16x16），不生成。
4. pixelavg_pp 8x8（764 万次）无候选。
5. **按 P1 规则不生成新桶**：唯一带正候选的 satd8 已注入；其余桶要么
   无候选要么候选为负。像素族剩余的潜在收益低于 0.5 E2E 点且无现成
   路径，等待新算法（如 SAD 4-way 合并）再评估。
