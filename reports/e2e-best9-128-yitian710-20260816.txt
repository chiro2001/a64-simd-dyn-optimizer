Issue found and fixed (2026-08-16)
----------------------------------
First full-bundle E2E FAILED the bit-exact gate:
  optimized md5 505d205dc98620b7622daf3a52c564fb != baseline
  (stable; reproduced via injection bisect).
Bisection (tools/bisect_vl128_e2e.sh, one-kernel-at-a-time E2E):
  every kernel except sao-stats-e1 passed; sao-stats-e1 alone reproduced
  the exact failing md5.
Root cause: generated adapters for sao-stats-e1/e2/e3 called a
single-row SVE2 kernel per row, but the kernel negates upBuff1 at entry;
upstream negates once before the row loop. For endY > 1 the adapter
double-negated, computing edge = D_y + D_{y-1} instead of D_y - D_{y-1}.
  - e1/e3: negate the 64-byte upBuff1 between rows;
  - e2: swap upBuff1/upBuff and negate between rows (upstream swaps).
The 20k manifest verifiers used endY=1 (single-invocation drivers), so
they did not catch the multi-row state bug.
Fix landed in tools/build_preload_so.py (adapter templates); bundle
regenerated; full 19-kernel E2E now bit-exact PASS.
